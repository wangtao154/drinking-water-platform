# AI 审计日志备份与恢复操作手册

## 适用范围

本文适用于 `ai_assistant_audit_log` 与 `ai_assistant_audit_chain_state`。该日志仅保存调用元数据和脱敏摘要，不保存完整提问、完整回答或原始敏感数据。

## 权限要求

1. 审计页面和完整性校验接口仅授予具有 `SYSTEM_AUDIT` 权限的必要后台角色。
2. 日常应用账户不得使用数据库 `root` 账号开展人工维护；数据库直连仅限受授权运维人员，并纳入运维审批和操作审计。
3. 审计日志内容不可通过后台页面修改；数据库层会拒绝未到保留期的删除和不可变字段的更新。

## 每日备份

1. 在运行 Docker 的主机执行导出，仅包含两张 AI 审计相关表。
2. 备份文件使用日期命名，保存到受访问控制的目录，并至少保留 6 个月。
3. 对备份文件生成 SHA-256 校验值，校验值与备份文件分开保存。

示例命令中的密码应通过安全的运维凭据管理工具传入，禁止写入脚本、文档或聊天记录：

```powershell
docker exec -e MYSQL_PWD="<数据库密码>" dw-mysql mysqldump -uroot --single-transaction --set-gtid-purged=OFF drinking_water ai_assistant_audit_log ai_assistant_audit_chain_state > .\backups\ai-audit-YYYYMMDD.sql
Get-FileHash .\backups\ai-audit-YYYYMMDD.sql -Algorithm SHA256
```

## 每月恢复演练

1. 先在隔离的测试数据库恢复备份，禁止直接覆盖生产库。
2. 校对两个表的记录数量、最新调用时间和 SHA-256 备份校验值。
3. 以有 `SYSTEM_AUDIT` 权限的测试账号登录，在“系统管理 - 审计日志 - AI 助手审计”点击“校验完整性”。
4. 结果必须为“完整性校验通过”；若存在迁移前历史数据，则允许显示“存在未封存历史记录”，并核对未封存记录数量。
5. 演练记录至少包含：备份文件名、恢复时间、执行人、校验结果、异常与处置结论。

## 恢复步骤

1. 停止涉及 AI 审计写入的 `ai-service`，保留主业务服务运行。
2. 先对当前生产表做一次应急备份。
3. 仅在获得负责人批准后，将备份恢复到目标环境。
4. 启动 `ai-service` 后在审计页面执行完整性校验，确认通过再恢复正常访问。

## 异常处理

- 校验失败：立即保留当前数据库与备份副本，暂停对审计表的人工维护，按最早异常记录定位。
- 备份校验失败：禁止恢复，改用上一份校验正常的备份。
- 未封存历史记录：表示记录产生于哈希链上线前，不等同于篡改；应保留并从上线后的首条封存记录开始持续校验。
